When the task is a product idea, design or revision, load the design-product skill, references/execution-kernel.md and references/phase-routing.md, then only the active pack and triggered sections. Read a principle leaf before citing, not every leaf or compatibility playbook up front.

`/design-product` is that skill. Antigravity turns its name into the slash command. Apply references/discovery-interview.md for new briefs, interviews, advances or changed core premises. A new brief without advance stays Understand even for advise/Full; sufficient context needs no interview. Next, next gate, continue, proceed, approve, yes to a summary, or naming the next phase opens it now without another discovery/confirmation/level question. Clear an Understand cap and repeat-discovery gate; missing facts stay unknown and unsafe behavior is excluded. Bare "no questions" without continuation returns only discovery summary, gaps and research plan. Otherwise run one phase and stop. Advise recommends inside the phase; a level only caps outputs.

Leaf skills under `skills/` are steps that skill calls. Do not apply a leaf skill as the whole job.

Write the package in the project being designed, under `docs/product-design/<slug>/`. Leave the decision to build with the person. Do not write production code in this task. Do not start technical design from this skill. `/technical-design` runs only after the person approves Specify or asks to brainstorm the technical design.

Read relevant references/learning-loop.md sections for actual synthesis, test planning before detailed artifacts or supplied results, not every task. Levels cap artifacts, not evidence maturity. Keep complete screen/state mockups separate from limited learning material, and hand off post-release review ownership rather than claiming to operate the service. Keep this primary as the product-domain orchestrator: retain decisions and phase authorization, delegate execution under references/orchestration.md to research, exact-path Markdown authoring, artifact and review leaves. Parallelize independent read-only work, serialize canonical writers, and report blocked delegation rather than writing inline.
