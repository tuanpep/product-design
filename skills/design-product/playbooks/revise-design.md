### Revise an existing design

**You own the update. Withdraw a stale readiness claim before you edit.**

Apply [the discovery interview and context gate](../references/discovery-interview.md) when a core premise changes or is invalidated. Interview only for the affected gaps, and only when they have not asked to continue. An advance request applies the correction, records any remaining gap as unknown, and opens the next phase without another question. Do not reopen the gate for unchanged premises or cosmetic edits. Preserve existing artifacts without extending stale claims while a revision is still blocked.

When [advise mode](../references/advise-mode.md) is on, do not stop to ask which revision to make or which option to take inside the affected phase. Apply the new evidence, recommend the updated design, label new choices **proposed**, and leave human edits in place. Open a later phase only when this message asks to go next.

1. Read the existing proposal, including its decision, distinct user and business/service outcomes, selected opportunity, evidence, unresolved risks, level/profile, and status. Read the newly supplied information verbatim. Ingest supplied research/results through [the learning loop](../references/learning-loop.md): provenance, method/audience/version and missing details; attributed observations; patterns including contradictions; findings and opportunities; comparison with prior decision criteria. Never invent sessions, counts, quotes, or actual execution. State supported, weakened, reversed, or inconclusive and why.
2. Name the earliest premise that changed. List the dependent claims, opportunities, options, evaluation questions/methods, journey steps, rules, measures, first-release scope, and checks affected by it. Re-select the opportunity before reopening solution alternatives. If alternatives change, update `plan-evaluation` before detailed experience/screens, choosing question → method → least necessary artifact.
3. Revisit only the affected product work. `frame-problem` when the problem itself changed. `map-stakeholders` when roles or owners changed. `discover-needs` for new context. `survey-existing` when the existing project gained, lost, or changed something this design reuses. `define-requirements` for needs or requirements. `explore-solutions` when the chosen approach is open again. `model-process` when handoffs changed. `design-experience` for the journey. `design-screens`, `write-content`, and `mockup-drawio` when screens, states, copy, or a layout choice changed. `drawio` when a journey, process, or navigation diagram changed. `context-drawio` when a dependency on another system changed. `plan-evaluation` when the risky assumption or its test changed. `map-stories`, `model-domain`, `define-rules`, and `specify-build` when the slice, data, rules, or checks changed. Read the principle leaf whose trigger the new evidence hits. Preserve unaffected evidence, IDs, and decisions. Do not silently promote a proposed choice to an approved one. Do not start or continue the technical design phase: do not run `select-views`, view skills, or `record-decisions`. If `technical-design.md` or a build diagram already exists and this change makes it stale, say which file is stale and that `/technical-design` is the way to update it.
4. When an owner answers an open question, replace the proposed default in `build-spec.md`, mark it approved with the owner and date, and update every reference to that ID.
5. Update each file in place. Mark superseded claims and the reason for the new recommendation in the decision history. Reconcile screens, the mockup, diagrams, and build spec with the text. Do not overwrite human edits without agreement.
6. `review-design` and `decide-next` on the whole package, against its level/profile, not an automatically expanded Full handoff. Keep context sufficiency, evidence confidence, specification completeness, and human approval separate. Update post-release learning ownership, guardrails, and review triggers if affected; implementation remains external.

**Reply:** what changed, which principle changed a choice, what remains unverified, and who makes the next decision.
