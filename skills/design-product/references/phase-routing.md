# Phase-specific loading

Use [the execution kernel](execution-kernel.md) plus exactly the active phase below. Select from the request and existing package, not file count/polish. An explicit advance opens the next named phase with gaps unknown; no extra confirmation/level turn. A new brief with no advance remains Understand. If a phase boundary remains genuinely ambiguous without an advance, ask only the necessary question. Do not run later phases because Full/advise was named.

| Active operation | Load | Do not preload |
| --- | --- | --- |
| Understand/new brief | [Understand](phases/understand.md) | Shape/Specify/Technical methods, complete-screen formats |
| Shape | [Shape](phases/shape.md) | Build/technical formats and all principle leaves |
| Specify | [Specify](phases/specify.md) | Technical views and screen component libraries |
| Technical | [Technical](phases/technical.md) | Product discovery/alternatives unless invalidating evidence requires product revision |
| Review | [Review skill](../../review-design/SKILL.md) | Every plugin reference; inspect supplied package artifacts, not the whole catalog |
| Revision/results/copy edit | [Revision](phases/revise.md) | Unchanged phase procedures and unrelated models |

Read specialist entry instructions only for actual tasks and references by heading/trigger; grep/headings can locate a relevant section before a bounded read. Do not reload identical files already available in this context. Read additional context when a source is changed, insufficient or contradictory; token budgets never excuse a safety/correctness gap.

The older [new-idea playbook](../playbooks/new-idea.md) and [workflow](workflow.md) remain detailed compatibility/method references, not compulsory full reads. Their gates and safeguards still apply; use their relevant sections only when the current pack requires clarification.
