# Bounded revision

Read the changed source/result and existing decision/owner, phase/cap and named handoff. For supplied results load only the [learning-loop ingestion](../learning-loop.md) procedure: provenance/method/audience/artifact version, observations separate from interpretation, contradictions, findings, comparison with prior criteria and supported/weakened/reversed/inconclusive impact. Never invent execution, quotes or task times.

Find the earliest changed premise and affected definitions/claims/artifacts. Withdraw invalid dependent readiness before claiming closure. Preserve unaffected evidence, IDs, human edits and supersession history. Reopen discovery only for an affected core premise without an advance; cosmetic/copy edits do not trigger interviews. Explicit advance leaves missing facts unknown and excludes unsafe behavior.

For a consequential change, update Decision history with date, changed premise/source, prior and revised decision, affected IDs/documents, prior results still applicable with rationale, results requiring reassessment, readiness impact, next owner and human decision status. No separate change-request file. Update affected assumption assessments or dependency resolution evidence using the [uncertainty lifecycle](../learning-loop.md#track-consequential-uncertainty). Do not declare a dependency resolved merely because its plan was written or an assumption supported merely because a case completed.

For legacy format migration follow [template migration](../documentero-templates.md#existing-packages-and-office-documents). Do not rewrite an older package for a copy-only request. In migrated/new packages reconcile requirements in the SRS, procedures/results in the test plan and matrix coverage in SRS Appendices; retain prior criteria and real results with provenance. Update affected C cases and matrix status when requirements change; old results do not verify new behavior.

Preserve historical results with the version/criteria they checked. If changed behavior invalidates a prior pass, retain the old result as historical evidence in the plan, set the current case to planned with Actual result: not run or blocked with its blocker, and reconcile matrix status. Record why an unchanged result remains applicable instead of carrying passes forward silently. Document updates, case execution, and human approval are separate states.

Load only the affected specialist and phase sections. Changed opportunities/alternatives precede revised evaluation/experience. Change the authoritative owner first, then authorized dependents, including copy and translations. Technical redesign is outside this plugin; readiness withdrawal alone permits no technical mechanisms. Report stale files/IDs, impact, owner or Unknown and next authorized update where scope prevents reconciliation.

Use [the detailed revision playbook](../../playbooks/revise-design.md) only for an ambiguous revision dependency or method question. Review changed work and consequential shared dependencies against the named handoff. Preserve findings/repair evidence; one supported correction/recheck cycle, then report unresolved blockers rather than repeated agent-to-agent passes. Standalone review remains read-only; repairs require the owner/request's authorization. Existing next-action findings are consumed, not another whole-package review.
