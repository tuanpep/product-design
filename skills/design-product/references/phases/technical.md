A concern needs an adequate representation, which can be cited existing text; omitted diagrams do not waive obligations. Missing product premises become named gaps, not a silent rerun of Specify.

Assess consequential invariant → owner → enforcement → failure/uncertainty → transition/recovery → verification before mechanisms. Distinguish competing/stale writes from duplicate retries, partial/ambiguous outcomes, consumer compatibility, async delivery/order/correlation semantics and operational rollout/recovery. Valid schemas, filled headings and matching status strings prove none of these.

Only included view owners run, initially in dependency order: `design-data`/`erd-drawio`, `state-drawio`, `design-composition`/`design-dependency` (shared reasoning once), `design-contract`, `sequence-drawio`, `design-deployment`, `dataflow-drawio`/`assess-threats`, existing `define-rules` only if affected, then `record-decisions`. Security/feasibility concerns can require earlier targeted investigation. Do not load every owner up front. Reconcile consequential dependencies, not mechanically repeat all views.

Keep conceptual/internal/external schemas distinct with deliberate mappings. Preserve authoritative contracts/models unless revision is authorized. Settle logical identifiers/cardinality before physical defaults. Record architecturally significant choices even if reversible; local names/types alone do not need ADRs. Detect real dependency cycles; no invented topological order or automatic failure lifecycle states. New blockers withdraw dependent readiness in technical/build/proposal files within scope.

Correct supported wording within scope, never add/redraw screens; report exact stale mockup instances and product-revision owner.
