# Execution kernel

Read once per active context; reload only if changed. Skills are procedures, not agents. Calling a skill does not require a child session.

- Establish target package, request/authorization, current phase, output cap/profile and named handoff. Preserve IDs, authoritative definitions, accepted decisions and unaffected human edits. Do not invent evidence, expected outcomes, policy or human approval.
- One phase per run unless this message explicitly opens the next. Full, advise or "whole package" alone do not advance. Next/continue, approval or naming/brainstorming the next phase opens it without another discovery/confirmation/level question. Missing facts stay unknown; exclude unsafe behavior. [Discovery policy](discovery-interview.md) owns exact semantics; load it for new briefs, interviews, advances or changed core premises, not unrelated edits.
- Understand: frame decision/needs/context. Shape: compare safe alternatives, plan evaluation before detailed artifacts, then experience and allowed screens. Specify: one bounded build spec. Technical: separately requested Full continuation, only justified views. Production code is outside this plugin's task.
- Levels cap outputs, not evidence or approval: Understand only discovery; Design documents no screens; Mockup allows complete screen handoff but no build spec; Full allows Specify, not automatic Technical. Omit artifacts rather than silently raising the cap. Legacy absent headers retain their existing contract. Load [output standard](output-standard.md) only for applicable output/profile details.
- Protection/inclusion, meaningful recovery and interacting-boundary coverage, single ownership and testable outcomes remain safeguards even without a leaf read. Load principle leaves only for a consequential choice, conflict or citation, and read before citing. A proposed reversible default cannot close a blocking safety, policy, authorization, feasibility or integrity question.
- Standalone review is read-only. Authorized repairs belong to the phase owner, retain the original finding/evidence, change the owning definition first and recheck affected dependents. Withdraw dependent ready claims within scope; otherwise identify exact stale claims/files and owners. Never silently resolve disputed human policy. Coherence, evidence confidence and named delivery readiness are separate verdicts, not permission to build.
- Given, observed, inferred, proposed and unknown are different. A plan/prototype/agent inspection is not actual research, feasibility or participant success. Supplied results retain provenance, observations versus interpretation, contradictions and decision impact. Load learning-loop sections only for the current research/synthesis/evaluation task.
- Write authorized artifacts once; return paths/versions, decisions, located findings, performed checks and limitations, not copies of entire XML/schema/research outputs. Inspect consequential sources rather than trusting worker summaries. Structural validators do not establish semantics, rendering or conformance.
- The active owner controls human questions, phase authorization, canonical text and final integration. Optional delegation follows [the bounded contract](orchestration.md); do small/tightly coupled work inline. No automatic fan-out, recursive workers or endless review/repair loops.

For policy ownership or disputed scope use [specialist execution](specialist-execution.md). Do not preload its linked graph. For each phase load only its pack from [phase routing](phase-routing.md), plus triggered method/format sections. A new context must receive relevant facts/limits; switching agents in the same session does not reset history.
