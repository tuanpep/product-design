# Explore Solutions

Load [the shared execution contract](../design-product/references/specialist-execution.md) only for a direct call without an owner, or a scope/policy conflict. Prefer the owner's kernel and active pack. Principle links below are selective candidates, not mandatory preloads; read a leaf before citing it.

Without an advance request, missing core context stays in Understand. An explicit advance request opens Shape without another interview or summary-confirmation checkpoint: retain unknowns and exclude unsafe behavior. This skill adds no separate gate; [discovery policy](../design-product/references/discovery-interview.md) owns exact semantics when advance or interview is contested.

Use precedence in [the principles index](../design-product/references/principles.md) only when principles conflict. Load [principle-see-the-whole-service](../principle-see-the-whole-service/SKILL.md) when it could change whether to build, not as an automatic preload.

1. Reuse applicable synthesis and opportunity; load relevant [learning-loop](../design-product/references/learning-loop.md) sections only when checking provenance or revising the opportunity. When advancing with incomplete context, state a bounded provisional hypothesis with missing facts unknown; do not invent findings or restart the interview. Without an advance request, investigate the consequential gap through `discover-needs`.
2. Brainstorm with the human before evaluating when they ask to brainstorm or the direction is still open. Load the [brainstorming sequence](../design-product/references/discovery-interview.md#brainstorm-after-understanding) only then. Include the current or no-build baseline and plausible alternatives, including non-software approaches when credible.
3. Compare likely value, user effort, feasibility dependencies, cost uncertainty, risks, operational load, and reversibility. Use unknown rather than guessed numbers.
4. When the target is an existing project and `survey-existing` has not run, run it first. Start from its must-reuse and should-reuse findings. Recommend the option that survives the higher principle. Name the principle that decided it and the principle it cost. Recommend stopping, reusing, or extending when that meets the outcome. A new part needs the findings that cannot.
5. Identify assumptions across desirability, usability, feasibility, viability, and ethics, prioritizing weak evidence and serious consequences. Run `plan-evaluation` now, after alternatives and before detailed `design-experience` or screens. Choose the question and method before the least necessary artifact; the recommendation remains provisional until the relevant evidence and owners support it.

Label recommendations **proposed** and name the person who can accept consequential trade-offs. Do not present a comparison table as evidence that the winning option was tested.

**Reply:** the recommended option, the rejected options, the principle that decided the trade-off, and the reversing assumption.
