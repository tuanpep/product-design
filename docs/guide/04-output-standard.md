# Check output quality

Review the decision brief, SRS and Test Plan together against [the output standard](../../skills/design-product/references/output-standard.md). No output validator is bundled.

## Check document structure

- Supported standard/version, real dates, required headers and ordered nonempty sections.
- product-design/1.3 Phase/Level/profile/gate agreement: only a brief in Understand, plan from Shape, SRS only at Full Specify.
- SRS seven Documentero-based sections, A acceptance outcomes, R requirements and matrix column/coverage structure.
- Plan's ten source-template sections plus Test cases; stable C IDs, required fields, type/status agreement and actual-result/evidence fields for finished checks.
- Matrix → C case and reverse R/A references, defined needs/requirements/outcomes, matching case/matrix status, and one message catalogue.
- No screens, diagrams or technical design in new-format packages. Legacy 1.0–1.2 and build-spec/1.0 remain readable under their versioned rules.

The local starters live in [the template directory](../../skills/design-product/templates/). Source/adaptation boundaries and manual Office use are documented in [template selection](../../skills/design-product/references/documentero-templates.md). Automated Office export is not implemented.

## What still needs review

Structural checks cannot prove that a requirement is justified, a source supports a claim, an expected outcome is correct, a procedure sufficiently checks it, or an actual result is authentic. They cannot infer consent, meaningful accessibility, human approval or product demand.

Review semantic traceability in both directions, denied/recovery boundaries, rule/permission/copy consistency, evidence status and consequential blockers. Check actual versus planned work. Judge the named phase and slice rather than demand future artifacts. A coherent plan can remain unexecuted; execution required by a decision cannot be waved away by marking the SRS ready.

## Review scope, authority and closure

Standalone review reports findings without edits. Authorized repair changes the owning definition first and reconciles affected dependents. Keep original findings, supported repair and recheck evidence. Report out-of-scope stale files with owner/next action instead of claiming package-wide closure.

Return **Design coherence**, **Evidence confidence** and **Delivery readiness** separately. Agent review is not product/domain, engineering or testing sign-off. No generated status is permission to build or launch.

Installed-host behavior and real product learning need [isolated trials](05-skill-evaluations.md). Document completeness alone does not establish either.
